# 工作原理

> 这份文档写给想改代码、或想知道「为什么这句没翻」的人。
> 只想装来用的话，看 [README](../README.md) 就够了。

---

## 一、为什么要分三层

Vortex 的界面文字来自三个完全不同的地方，一种手段治不了全部：

| 来源 | 例子 | 谁能管 |
|---|---|---|
| i18next 语言包（走了 `t()`） | 菜单、按钮、设置项、对话框 | 语言包 |
| 代码里写死的字符串 | `Refresh List`、`Sort by Deploy Order`、`View page` | 只能 DOM 层 |
| 第三方扩展注册的内容 | 扩展的页面标题、游戏卡片名、模组简介 | 只能 DOM 层 + 模型 |

所以本项目分三层，共用同一份 `pack.json`，避免「菜单叫设置、正文叫偏好设置」：

| 层 | 负责 | 代价 |
|---|---|---|
| 界面语言包 | 走 `t()` 的 6185 条（字符串叶子，= 语言包 manifest 的 `entries`） | 0 token，重启生效 |
| DOM 实时翻译 | 硬编码文案、扩展标题、游戏卡片 | 词库命中 0 token，否则走模型 |
| 批量翻译 | 模组名、合集名、更新日志、简介 | 走模型，结果落缓存 |

## 二、语言包是怎么接管的

Vortex 的 i18next 用 `MultiBackend` 加载语言包，**只认一份来源**，优先级：

```
%APPDATA%\Vortex\locales\<lang>\          ← 用户级（我们的目标）
某个第三方翻译扩展的 zh/ 或 locales/zh/    ← 扩展级
<安装目录>\resources\locales\<lang>\       ← 内置，只有 en
```

两个关键事实（都在 `app.asar` 里核实过）：

1. **只认一份**。同时装两个中文包，只有一个生效 —— 后来装的或优先级高的赢。
2. **按当前语言选目录**。宿主读 `settings.interface.language`，值是 `en` 时不会去看 `locales/zh/`。
   所以 README 让你把界面语言改成中文，不单纯是「选择语言」，而是**不选就不会加载**。

`locale-pack.js` 做的事：把包内的 `pack.json` **整份**写成**一个** `locales/zh/common.json`。

它不读别人的汉化包当基底，也不读 Vortex 内置的 `en` 语言包 —— 能收的译文在构建期就已经
烧进 `pack.json` 了。所以 `locales/zh/` 是**写入目标**，不是词库来源。

一个文件为什么够：Vortex 的 i18n 初始化参数是 `fallbackNS: "common"`，
任何命名空间查不到的 key 都会回退到 `common`。

### 不覆盖别人的东西

`locales/zh/` 是共用目录。所以：

- 每次写入前算磁盘上 `common.json` 的哈希，与 manifest 里记的不一致 → 说明被别的包改过 → 先备份到 `backup-<时间戳>-foreign/`
- 备份失败就中止本次写入，不硬盖
- 「移除接管」只在「文件确实还是我们写的那份」时才删
- 清理旧文件只删 manifest 记录过的，不按「译文像不像我们的」反推

## 三、DOM 层：为什么以「段落」为单位

早期按文本节点翻，结果是把一句话拆成碎片：

```
页面： <p>Links are now <a href=x>exposed over IPC</a> (<code>nxm://</code> links)</p>
碎片： "Links are now" / "exposed over IPC" / "(nxm:// links)"
```

碎片没有上下文，模型要么照抄，要么吐不出 JSON，整批失败、堵死队列。

现在以「最内层块级元素」为单位，先序列化成带占位符的串：

```
Links are now <i1>exposed over IPC</i1> ({{2}} links)
```

- `<iN>` 对应可交互元素（`a` / `b` / `span`），回填时把原节点 clone 回来
- `{{N}}` 对应不可交互元素（`code` / `img` / `svg`），回填时插回去
- 模型返回中文后，按伪标签重新组装，链接照样能点、图标照样在

### 回填只改文本，不删节点

`applyInPlace` 只写 `node.nodeValue`，不增删任何元素节点 —— React 维护的结构没变，
它下次更新时不会找不到节点。

任何一层结构对不上（模型把嵌套拍平了），就整体 `rollback()`，这一块留英文。
宁可少翻一句，也不能让界面白屏。

整块重建（`innerHTML`）只在 `CONTENT_SEL` 白名单内（changelog / description / markdown / modal），
而且必须先过 `canBlockReplace()`：元素里不能有按钮、输入框、`[data-zh-skip]`。

### 什么时候跳过

- 已经是中文（CJK 判定）
- `<code>` / `<pre>` / `<kbd>` / 图片 / SVG
- 版本号、文件大小、颜色值、CSS 类名、URL、本地路径
- 纯专名：`UE4SS`、`LogicMods`、`CR4Player.CanApplyOilOnItem`
- 作者名（只翻 `By` / `Created by` / `Uploaded by` 前缀）
- 扩展自己的设置页（`[data-zh-skip]`），但设置页里嵌的更新日志例外

## 四、模组名走的是另一条管线

### 两个翻译按钮，语义必须分开

`translateAllFresh()` 有一个 `keepExisting` 开关，只有设置页的「立即翻译」传 true：

| 入口 | 已有译文 | 失败/被放弃的条目 | 界面文本缓存 |
|---|---|---|---|
| 立即翻译（只补缺的） | 不动 | 重试 | 不动 |
| 清空缓存并全部重翻 | 先删掉 | 重试 | 一起清 |
| 一键汉化（全部重翻） | 先删掉 | 重试 | 不动 |
| 升级后自动重建 | 先删掉 | 重试 | — |

早期两个按钮都无条件删译文，等于「立即翻译」偷偷清了一次缓存；而清缓存按钮反过来只清不翻，
提示却写「正在重翻」。现在清完真的会接着翻，成功后退掉 `_rebuild` 欠账标记。

界面文字翻完只存在于屏幕上——DOM 层把译文贴回节点，Vortex 一重渲染就没了。
模组名不一样：它出现在模组列表、下载页、合集健康检查、按钮提示等无数地方，
逐处贴不现实，所以它走**状态层**：直接写进 Vortex 自己的数据。

| 条目 | 写进哪 | 为什么 |
|---|---|---|
| 已安装模组 | mods 表的 `customFileName` | Vortex 显示名的第一优先来源 |
| 下载记录 | `modInfo.name` | 写的是这个字段。读取时先取它，没有才回落到 `nexus.fileInfo.name`。**绝不写 `nexus.fileInfo.name`** —— 那会让 Vortex 重新计算显示名，产出「英文 - 中文」的杂交名 |

写之前会把英文原名备份进 `zhSourceName`——右键「还原英文」、换名重翻，都靠它找回原文。

### 状态层是成果，缓存只是影子

| 层 | 内容 | 「清空缓存」动不动它 |
|---|---|---|
| 状态层 | `customFileName`、下载行名字 | 不动——已落地的成果 |
| cache.json | 原名 → 中文 的键值对 | 清掉，可再生 |
| domCache.json | 页面译文缓存 | 清掉，可再生 |

由此有个反直觉的事实：**删掉缓存键，模组名不会重翻**。「要不要翻」主要看状态层里
是否已是中文——状态层是中文的行，所有收集线都当「已翻过」跳过。
这就是「删了缓存它还在」的原因；右键「重新翻译此名」要连状态层一起处理，也是这个道理。

0.20 起缓存还参与一道**辅助**判定。模型译文写进缓存前要过一道验收（同时看原文和译文），
而早期读出口只有译文、看不到原文，只能用更严的判据自判；两者结论不一致时，界面上已经是中文，
自动轮却仍会把同一条反复送模型重翻。现在收集阶段会同时核对两件事：缓存里这条译文是否过
写入口那道验收，以及状态层的显示名是否正是这条译文；两条都成立才标记为已处理，并在真正
执行翻译的循环里跳过。缓存只是辅助证据，不是主判据——缓存被清时，状态层仍然是成果。

### 遮蔽是硬保证，提示词只是自觉

名字批次送模型前，词库里的品牌词、游戏名、工具名全部替换成『固定译名』占位符，
模型返回后再还原——模型见不到原文，就不可能翻错。在提示词里写「请保留品牌词」
模型会无视（实测），遮蔽不会。

### 译文验收：不合格不落缓存

7B 级模型对模组名会自信地犯三类错：整串照抄原文、用引号把名字包起来交差、
只翻一半留一截长英文。这类译文经验收不合格就不写入缓存；同一名字重试满 3 次
自动暂停（7 天后或换模型自动恢复），不无限烧调用。

### 词库更新后的存量对账

词库新钉一个译名，之前翻好的存量译文不会自动跟上。启动时有一道**对账**：
用与送翻同一套遮蔽判据扫缓存，发现缺新固定译名的旧译文就删键重翻。
判据必须同源——两套判据会「对账说行、送翻说不行」互相打架。
重翻没完成的下轮启动再审，自动收敛。

半中半英的译名（`ModSkillSlotPages重制版1.8` 这类）另有词级补翻：拆驼峰、复用词表，
试满 3 次落定英文原文。下载页的完整文件名行（`… 1.0.4 1.0.8-日期-hash.zip`）
剥掉版本尾巴只翻短名、尾巴原样拼回，零模型调用。已卸载的模组、下载记录里的条目
走同一条管线：启动数秒后自愈 + 渲染层兜底，不必装上模组才翻得到名字。

自愈救回条目时会弹一次通知（救 0 条不弹）。自动化没有可见回执，用户就会反复
怀疑它没跑、反复手点重翻——这比不提示更费。

### 同批不混游戏：按 gameId 分批

一批里混进多个游戏的模组名时，模型会拿别的游戏的上下文去猜：批里有条「Valheim 扩展包」，
同一批的 `EpicValheimsAdditions` 就会被译成「英灵神殿」——它没错，是**被邻居带偏**。

所以送翻前按 gameId 把条目分组，每组单独成批。代价是车数变多（每款游戏各装各的车，
装不满也要单独发），换来的是不再跨游戏串味。下载记录没有 gameId，落进同一个空串分组。

### 串行错位：长度对得上，内容整体位移

本地小模型遇到两条只差标点或版本号的名字时，会**少给一条译文、再把最后一条重复一次**
补足数组长度。条数刚好对上，所以「长度是否相等」这道检查原理上看不见它。
后果比漏翻严重得多：后面整段位移，界面上 A 模组显示的是 B 的译文。

两道证据取并集，命中就把对应条目单独重译：

- **词证据**：某条独有的拉丁词（≥5 字母）既没留在自己的译文里、又出现在别人的译文里
- **结构证据**：相邻两条译文完全相同，且两条源文不是「只差版本号/标点」那种本就该同译的情况

只对模组名生效。长文本单条重译贵得多，误判一次的成本不成比例。

这是**尽力而为**的兜底，不是根治：真错位很罕见，误报同样要付代价（多一次调用 + 可能盖掉
本来正确的译文），所以判据宁可漏判。它抓不到「只差版本号」的位移，那是有意放过的。

### 批量翻译也有进度

界面实时翻译的进度写在 `liveStatus` 里，但「清空缓存并全部重翻」这类**批量**路径
以前不写——用户点了按钮，铃铛说「正在翻译 N 条」，设置页那块面板却是空的。

现在批量路径有自己的一份状态（独立子对象，不和界面实时翻译抢同一个格子）：
已完成/总数、并发路数、正在发送的条目、最近完成的译文、失败数。
数字由 core 的回调推进，面板只做集合运算，不依赖条目顺序。

两个坑记在这：条目下标始终是**原始数组下标**（分批只是换了发射顺序，不需要偏移）；
一次批量结束要给收尾兜底（core 抛错时不能让面板永远停在「正在翻译」）。

## 五、模型调用：窗口是动态算的

模型的 `max_context_length` **不等于**实际加载的上下文。
LM Studio 的 `/api/v0/models` 里 `loaded_context_length` 才是真的（实测有机器只加载 8192，模型标称 262144）。

写死 `max_tokens: 4096` 会撞上实际只有 4096 的窗口，服务端返回
`Context size has been exceeded`，整批作废 —— 这是早期「整页英文」的真正原因。

现在的算法（权重为 2026-10 在 LM Studio + 7B 级模型上的实测值，全部刻意高于实测）：

```
estIn    = estInputTokens(输入) + 系统提示词估值 + 64
           estInputTokens 按字符分类加权：ASCII 0.25 / 汉字 0.68 /
           假名谚文全角 0.95 / emoji 符号 1.65 / 其他拼音文字 0.75，
           另对 ≥20 字符的无空格 ASCII 长串（URL、Base64）加收 0.5/字符
want     = 输入字符数 × 0.5（mod）/ 0.85（html、ui）+ 256   // 输出需求
room     = ctx - estIn - 128
if (room < 400 || room < min(want, 4096)) → 抛 CTX_OVER，上层劈半重发
outTokens = clamp(min(want, room, 4096), 256, …)
```

两个闸门缺一不可：只查输入，大批次的 `room` 会被吃得只剩几百 token，发出去必被
`max_tokens` 截断整批作废；输出估低了同样截断（短模组名实测约 0.4 token/源字符，
含版本号和术语标记开销，所以 mod 取 0.5）。

真实 400 里能从报错学窗口（请求量和窗口同时出现时取小值），但**解析值等于当前估值时不动**——
那说明探测本来就对，是估算低估，该劈批而不是砍窗口。

超过 3000 字符的块按句子切成约 800 字符的小片，只在伪标签外部切，保证每片 `<iN>` 配对完整。

## 六、失败状态机

`failed` 里的数字有明确含义：

| 值 | 含义 | 行为 |
|---|---|---|
| `> 0` | 暂态失败（超时、解析失败、上下文超限、格式拒收） | 按 45 秒 / 4 分钟 / 15 分钟退避重试，最多 3 次 |
| `-1` | 不可译（模型连续两次原样返回，如纯专名） | 永不自动重试 |
| `> 3` | 重试用尽 | 永不自动重试 |

只有三个东西能解除终态：**用户点「清空缓存」**、**用户点任意翻译按钮**、**版本升级**（`failCache._ver` 变化）。

早期这里踩过大坑：有四个入口都能「复活」失败条目（三个定时器 + 可见复活 + 探活清空整表），
叠起来等于**永远在重试**，实测某个专名每 10 秒烧一次调用。现在**自动路径**只剩一个入口，
手动路径另算（见下）。

### 模型挂机暂停与手动优先级

连续两轮 0 成功且失败 ≥10 时，DOM 层判定「模型没在干活」，把 `modelDown` 置真并停止重试；
恢复靠一个 **120 秒一次**的探活：通过就清暂停、复活暂态失败、置脏重扫。

问题出在暂停期间：用户把模型开起来、按钮也点了，**界面文本仍要等满 2 分钟**才开始翻。
探活是自动路径的节奏，不该当成手动操作的响应时间。

所以 DOM 层额外导出一个 `kick()`：清 `modelDown` 与 `downStreak`、把所有 `failed > 0` 放行
（`-1` 不可译保留）、置 `docDirty`、队列非空就立刻 `flush`。`index.js` 在五个手动入口调用它：
立即翻译、全部重翻、右键「翻译此模组」、测试连接、清空缓存。

同一批修复还有三处口径：
- 启动自愈探活不过时不再整轮作废，改为 60 秒后补做、最多 3 次
- 手动重翻不吃 `isGivenUp` 名单（自动批次才吃），否则「清缓存后点重翻」会得到 `todo:0`
- 右键「翻译此模组」撞上正在跑的批次时排队等待，不再直接丢弃

### 「照抄」和「格式拒收」要分开

`finishOne()` 有五个「宁可留英文」的出口：占位符丢了、伪标签不配对、BBcode 坏了、长文漏译。
它们都返回原文。

如果上层把「返回原文」一律当成「模型不肯翻」，第二次就判 `-1` 永久封杀 ——
用户会看到「这段怎么重开都不变」。

所以现在被拒收的条目会额外记进 `_rejects` 集合，上层只有「逐字相同**且**不在 `_rejects` 里」
才按不可译处理。

## 七、准确性：三类一定会错的东西

7B 级模型不是不会翻，是**会自信地翻错**，而且错得很稳定。这三类不靠提示词，靠机制：

| 类型 | 实测错法 | 做法 |
|---|---|---|
| 游戏名缩写 | `TW3` → 《上古卷轴3》 | 内置对照钉进提示词；对照表里没有的缩写保留原文，禁止猜 |
| Vortex 专有词 | `profile` → 账号 | 术语表：profile=配置档、purge=清除部署、staging folder=暂存文件夹 |
| 文件路径 | `The Witcher 3\mods\xxx\` → `巫师3\mods\xxx\`，反斜杠还变 `/` | 发送前换成 `{{P1}}` 占位符，回来原样还原；占位符丢了就整条留英文 |

路径这条是硬要求：用户是照着路径删文件、放文件的，错一个字符就是白干。
**宁可整句英文，也不放行改过的路径。**

### 游戏名对照按需注入

759 条游戏名如果全塞进提示词，既浪费上下文又会被截断。
所以每次只注入「这一批文本里实际出现的那几条」（包含匹配，上限 40）。

### 其他后处理

- 繁→简（逐字符查表，表里只能放单字）
- 剥掉模型加的 `【】` / `《》` / 弯引号
- `&amp;` / `&lt;` 等实体在回填前解码
- BBcode 配对校验（模型会把 `[i]…[/i]` 写成 `[i]…</i>`）
- 译文里一个中文都没有 → 判定为「不是翻译」，不进缓存

## 八、数据放在哪

扩展升级是**整个目录覆盖**，所以运行时数据不能放在扩展目录里：

| 位置 | 内容 |
|---|---|
| `%APPDATA%\Vortex\vortex-modname-zh\` | `config.json` 配置、`cache.json` 模组名译文、`domCache.json` 页面译文、`failCache.json` 失败名单、`nameFail.json` 名字翻译失败熔断账、`collected.json` 采集记录、`translator.log` 日志、`seed-skip.json` |
| 扩展目录 | `pack.json` / `gamenames*.json` / `domCache.seed.json` 等静态资源，以及全部 js |

首次启动会自动从扩展目录迁移旧文件，翻过的东西不会白翻。

写盘统一 `.tmp` + `rename`（原子）并留失败日志，日志超 1 MB 轮转。

配置单独一套节奏：设置页输入框是**边填边存**（没有保存按钮），但每敲一个字符写一次盘没必要，
所以 `config.json` 改为停止输入 **400 毫秒**后落盘。注意**只延迟写文件**，内存里的 `cfg`
仍然立即更新 —— 否则填完地址马上点「立即翻译」，翻译层会把延迟前的旧配置读回来、报「未配置」。
两个读盘的地方（翻译入口、设置页 init）在读取前强制 `flush`。

## 九、目录结构

```
index.js              入口、设置页 UI、模组名批量翻译、缓存读写、实时状态
dom-translator.js     DOM 兜底层：扫描、判定、序列化、回填、队列、重试
translate-core.js     模型调用层：HTTP、提示词、占位符保护、分批、JSON 解析
locale-pack.js        语言包接管：把 pack.json 整份写进 common.json
pack.json             界面词库（6185 条，按字符串叶子计）
gamenames.json        游戏固定中文名（759 条）
gamenames-keep.json   明确保持英文的名单
domCache.seed.json    种子译文（清缓存升级后垫底）
config.json           出厂配置（接口地址为空）
```

教你怎么改不弄坏；想了解每条纪律的来历，读 [DEV-NOTES.md](../DEV-NOTES.md)，
里面每条都对应一次真实故障。
